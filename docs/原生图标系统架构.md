# 原生图标系统架构（NativeIconRegistry）

> 本文是 Molan 原生图标管线的**权威说明**：架构、契约、关键设计决策、使用方式与历史教训。
> 任何涉及「图标显示 / 获取 / 缓存」的改动，先读本文。

---

## 1. 一句话总结

**所有文件 / 应用图标统一走「内容寻址的原生图标注册表」**：后端用 `NSWorkspace.iconForFile` 取原生像素（与 Finder / Lemon 同源），编码为 128px PNG → SVG 信封 data URI，按内容哈希去重存储与传输；前端 `useNativeIcon` / `useNativeIconMap` / `NativeIcon` / `AppIcon` 渲染，未命中时 emoji 降级。

---

## 2. 架构总览

前后端各维护一份**镜像的双层缓存**，`contentID` 由图标内容哈希生成：

```text
pathIndex:     path → contentID        // 路径级：mtime 校验失效
contentStore:  contentID → SVG data URI // 内容级：同一像素内容全局一份
```

| 层 | 前端（`src/utils/nativeIconRegistry.ts`） | 后端（`src-tauri/src/lib/platform/native_icon_registry.rs`） |
|---|---|---|
| 内存 | `Map` 单例 + 订阅通知 | `OnceLock<Mutex<RegistryState>>` |
| 磁盘 | 无（信任后端） | `<app_cache>/native-icon-registry-v1/`：`blobs/<cid>.svg` + `index.jsonl` |

**去重效果（实测）**：927 个路径 → 108 种不同图标 → 磁盘 / 内存 / IPC 全部按 108 计数。旧方案（按路径缓存 PNG base64）为 927 × 870KB ≈ 490MB，新方案为 1 × 30KB/种 ≈ 3MB。

**数据流**：

```text
前端 resolve(paths)                    后端 resolve()
  │ 过滤未完整解析的路径（misses）        │ ① 逐路径 stat mtime
  ▼                                     │ ② pathIndex 命中 + mtime 一致 → 直接返回
IPC mole_native_icons_resolve ────────► │ ③ miss → file_icons_batch 编码
  ◄──────── entries + contents ─────────│     （分批主线程 + TIFF 指纹去重）
  │ 合并缓存 + notify 订阅者              │ ④ 写回 blobs + index.jsonl（内容寻址，幂等）
  ▼
useSyncExternalStore 触发重渲染，<img src> 命中
```

## 3. 数据契约

- **IPC 命令**：`mole_native_icons_resolve`（`src/constants/tauri-commands.ts` 登记为 `CMD_MOLE_NATIVE_ICONS_RESOLVE`）。后端为 `async fn` + `tauri::async_runtime::spawn_blocking`，**不占主线程**。
- **响应**（前端 `NativeIconsResponse`，镜像后端同名 serde 结构）：
  - `entries: Record<path, contentID>` —— **所有**成功解析的路径（含命中项）；
  - `contents: Record<contentID, SVG data URI>` —— **覆盖 entries 引用的全部内容**（跨会话重启时前端 contentStore 为空，必须随 entries 回传），批内按 contentID 去重，前端合并幂等。
- **类型定义**：前端 `src/types/mole.ts`（进程域 `icon` / `bundle_path` 字段）；后端 `native_icon_registry.rs`。
- **进程域单路径**：`resolve_single`（后端内部 API），供 `macos_running_apps::app_icon_svg` 在状态采集的 rayon 线程里按 bundle 路径取图，与文件域共享同一 contentStore。

## 4. 编码管线（`macos_file_icon.rs`）

### 4.1 128px 单表示重采样

- 旧实现 `setSize(128)` + `TIFFRepresentation` 只改逻辑尺寸、不裁剪数据，会把 NSImage 内所有分辨率表示（含 1024px 原图）打包导出 → 单图标 870KB。
- 正确做法：`NSImage(size: 128×128)` + `lockFocusFlipped` → `icon.drawInRect` 让 AppKit 按**目标尺寸重新合成单表示位图**（系统合成路径保留 alias 角标）→ `TIFFRepresentation` → `representationUsingType(PNG)` 编码。
- **为什么是 128px 而不是 64px**：macOS 在 64px 及以下表示不渲染 symlink 的 alias 角标，64px 会丢箭头（回归测试守护）。128px 编码后 CSS 缩到 28px 显示仍是 2x 视网膜清晰度。
- **SVG 信封**：PNG 包进 `<svg viewBox="0 0 128 128"><image href="data:image/png;base64,…"/></svg>` 再整体 base64，前端 `<img src>` 直接可用，CSS 任意缩放不失真。

### 4.2 symlink 必须原样传路径（红线）

`iconForFile` 对 symlink 返回「目标图标 + 左下角 alias 角标」，与 Finder / Lemon 一致。**禁止 `canonicalize`**——它会抹掉系统角标。回归测试 `probe_icon_for_file_keeps_symlink_badge` 断言：`/etc == /tmp`（同为 symlink）、`/etc != /usr`（角标存在）、`/usr == /private/etc`（真目录与目标共享）、`/etc != /private/etc`（禁止解析）。

### 4.3 TIFF 栅格指纹去重（历史教训，勿回退）

- `iconForFile` 对同一图标**每次返回新 NSImage 实例**（指针备忘实测 0 命中，共享实例假设证伪）→ 备忘 key 不能用实例指针。
- 备忘 key = **TIFF 栅格字节的 SipHash**（`tiff_fingerprint`）：内容相同即命中，跳过 PNG 编码 + base64。
- **为什么不用 `NSBitmapImageRep.bitmapData`**：实测 `imageRepWithData` 惰性解码下该缓冲区**读不到真实像素差异**——带角标与不带角标的文件夹图指纹完全碰撞（`0xf52c80438196052b`），会把不同图标错误合并。TIFF 字节是 PNG 编码的直接输入，像素差异必然体现在字节里。
- `encode_memo` 进程级，CAP=512（约 15MB 上限）；**满额时整体 `clear()` 重填**——备忘是纯优化层，清空不产生错误图，避免「永久拒收」在长会话后彻底失去去重能力。

## 5. 调度与并发

- **分批主线程调度**（`file_icons_batch`）：AppKit 约束编码必须在主线程。非主线程调用时按 `CHUNK=8` 分批 `DispatchQueue::main().exec_sync`，批间 `sleep(1ms)` 让出 runloop——每批结束主线程回 runloop 处理 UI 事件，图标**渐进出现**而不是冻结数秒（单张 ~10ms，583 张一次跑完会冻主线程 ~6s）。
- **锁外编码**：`resolve` 在进入批量编码前 `drop` 注册表锁，编码完再取锁写回。原因：① 编码可持续数百毫秒到数秒，不能阻塞状态采集（rayon 线程里的 `resolve_single` 快速路径）；② 消除「持锁等主队列 × 主线程等锁」的死锁窗口。编码产物内容寻址、写回幂等，并发竞争无副作用。
- **重 I/O 全部 `spawn_blocking`**（对齐 AGENTS.md 第 4 节）。

## 6. 前端使用方式

| 场景 | API | 说明 |
|---|---|---|
| 单路径 | `useNativeIcon(path)` | 订阅注册表，挂载时自动 `resolveSingle`（带请求去重） |
| 批量路径 | `useNativeIconMap(paths)` | 订阅注册表；快照按「版本 + paths + 值逐元素相等」缓存，值全等复用旧引用不触发重渲染 |
| 组件渲染 | `<NativeIcon path name isDir size />` | 注册表命中显示 SVG，未命中降级 emoji（`resolveStaticIcon`） |
| 应用图标 | `<AppIcon name path size iconSrc />` | Uninstall / Dashboard 复用；未就绪显示骨架屏；`iconSrc`（后端随帧下发）优先于 path |
| 批量预取 | `nativeIconRegistry.resolveIdle(paths)` | 20 路径/IPC + 批间 `setTimeout(0)` 让出事件循环，不阻塞渲染 |

**标准接入模式**（参考 Analyze）：页面拿到扫描结果后，先把目录/symlink/大文件路径丢给 `resolveIdle` 后台预取，列表用 `useNativeIconMap` 订阅——图标渐进出现，全部命中时零重渲染。

**emoji 降级是唯一兜底**：emoji 映射归 `src/utils/staticIconMap.ts`，注册表只存原生图标（关注点分离）。Clean / Optimize 页的 ant-design 图标是**分类装饰图标**，不对应文件路径，不走本管线。

## 8. 验证与回归

- **回归测试**：`cargo test --lib platform::macos_file_icon`（`probe_icon_for_file_keeps_symlink_badge`）——同时守护 symlink 角标与指纹碰撞两道红线。
- **视觉核验口径**：导出 PNG 肉眼比对——/Users 头像文件夹、/System macOS 字样文件夹、/etc /tmp 带 alias 角标、普通文件夹无角标、磁盘卷标、Calculator 应用图标。
- **性能实测**：139 路径首次扫描 → 1 次真实编码（1.47s，对照修复前 139 次 / 2.5s）；二次扫描 → 0 次编码。

## 9. 禁止事项（红线）

1. **禁止**新引入按路径维度的 PNG base64 管线、独立图标缓存（`iconService` / `useIcon` / `mole_get_icon_cached` 系已删除，勿复活）。
2. **禁止**绕过注册表直接调用 `iconForFile`——取图统一经 `macos_file_icon::file_icons_batch`。
3. **禁止**对传入 `iconForFile` 的路径做 `canonicalize`（丢 alias 角标）。
4. **禁止**用 `bitmapData` 做内容指纹（惰性解码碰撞，见 §4.3）。
5. **禁止**改小编码尺寸到 64px 以下（丢角标）。
6. 旧缓存目录 `icon-cache` / `icon-cache-v2` / `icon-cache-v3` 由 `LEGACY_ICON_CACHE_DIRS` 启动时一次性清理，不要在新代码中引用。

## 10. 已评估并搁置的优化项（勿轻易翻案）

| 项 | 结论 | 触发重评条件 |
|---|---|---|
| `CHUNK` 8→4 | 维持 8（当前无卡感） | 用户报告图标加载卡顿 |
| status 帧图标改指纹下发 | 搁置（改动横跨前后端契约） | 气泡开启时帧体积可感知 |
| blobs/index compact | 搁置（当前量级开机毫秒级） | 磁盘缓存体积显著膨胀 |
| 指纹提前到绘制前 | **否决**（重新引入指纹域碰撞风险） | 不会重评 |
