# 原生对话框方案（NSAlert）

> 本文档记录 2026-09 实现的 Molan 原生确认/提示通道全貌，供后续开发参考。
> 当前状态：核心通道已落地、编译通过、11 处调用点已迁移；旧确认通道（SystemConfirm / MoleDialog / moleConfirm / moleAlert）已全部退役删除。

---

## 1. 方案概述

全应用**唯一**的确认/提示机制：macOS 真原生 `NSAlert`（stock 样式）。

- **视觉**：垂直三行流 —— app 图标（居中） / 粗体文案（居中） / 原生按钮行
- **呈现**：调用方窗口可见时以 **sheet** 挂载（从窗口标题栏滑出）；不可见时回退 **app-modal** 居中弹窗
- **交互**：主按钮在右（默认蓝、回车触发）；取消在左（Esc 触发）；单按钮提示模式可选
- **实现**：Rust（objc2-app-kit）零自绘，完全依赖系统渲染 —— 与 Lemon Cleaner 同一套 stock 表现

### 三代方案演进（为什么废弃旧方案）

| 代际 | 方案 | 问题 |
|------|------|------|
| 一代 | `@tauri-apps/plugin-dialog` 的 `ask()` | 系统弹窗不受控，样式无法对齐产品视觉 |
| 二代 | SystemConfirm 独立 webview 窗口（`mole_system_confirm`） | 「假原生」：需要维护独立窗口、路由、HTML；视觉自绘成本高 |
| **三代（现行）** | **原生 NSAlert（`mole_dialog`）** | 零自绘、系统级渲染、随 macOS 版本自动适配外观 |

## 2. 参考基准：Lemon Cleaner 实证

最初误判「stock NSAlert 是左图右文、须自绘垂直流」，导致一代实现（accessoryView 自绘 64pt 图标 + 常规字重文案）比例失真。**实测 Lemon Cleaner 源码证明其就是纯 stock NSAlert**：

`Tools/LemonMonitor/LemonMonitor/Monitor/LMMonitorTabController.m:751-763`

```objc
NSAlert *alert = [[NSAlert alloc] init];
alert.alertStyle = NSAlertStyleInformational;
alert.messageText = NSLocalizedString(@"关闭状态栏后，所有功能（…）都不再生效。确定关闭吗？", nil);
[alert addButtonWithTitle:NSLocalizedString(@"取消", nil)];
[alert addButtonWithTitle:NSLocalizedString(@"退出状态栏", nil)];
NSInteger responseTag = [alert runModal];
```

**结论**：macOS 11+ 的 NSAlert 本身就是「图标 / 文案 / 按钮」垂直布局，stock 即目标形态，**禁止再自绘**。

## 4. API 契约

### 前端

```typescript
import { moleNativeConfirm } from '@/hooks/useMoleConfirm'

const ok = await moleNativeConfirm('确认清空历史记录？', {
  informativeText: '此操作不可撤销，历史记录将被永久删除。',
  kind: 'warning',          // 'info' | 'warning' | 'error'（映射 NSAlertStyle）
  okLabel: '清空',          // 主按钮（右、默认蓝、回车）
  cancelLabel: '取消',      // 取消按钮（左、Esc）；传 null = 单按钮提示模式
})
// ok: true = 点了主按钮；false = 取消 / 关闭 / Esc / 调用失败（安全兜底）
```

### 参数映射规则

| 前端参数 | NSAlert 对应 | 说明 |
|---------|--------------|------|
| `message` | `messageText` | **粗体**居中，自动折行（主文案） |
| `informativeText` | `informativeText` | 常规字重居中（副文案，可选） |
| `okLabel` | 第一个 `addButtonWithTitle` | 最右、默认蓝、回车触发 |
| `cancelLabel` | 第二个 `addButtonWithTitle` | 左侧；显式绑 Esc；`null` 时跳过 |
| `kind` | `NSAlertStyle` | `error` → `Critical`（自动带警告角标） |

### 旧接口 → 新接口迁移对照

| 旧（moleConfirm/moleAlert） | 新（moleNativeConfirm） |
|------------------------------|--------------------------|
| `title` + `message` 两层 | `message`（粗体）+ `informativeText`（常规） |
| `moleAlert(msg, {title})` 单按钮 | `moleNativeConfirm(title, { informativeText: msg, cancelLabel: null, okLabel: '知道了' })` |
| 无返回值（alert） | 返回值可忽略 |

## 5. 关键技术点（实现陷阱备忘）

> 以下每条都是实测踩过的坑，改动该文件前务必先读。

### 5.1 `messageText` 默认值是 `"Alert"`（必须显式覆盖）

`NSAlert` init 后 `messageText` 并非空串而是 `"Alert"`（AppKit 历史遗留）。不调用 `setMessageText` 会在弹窗顶部多出一行 "Alert" 标题。

### 5.2 按钮顺序：先加的在**最右**

AppKit 横向排布为 trailing → leading。`addButtonWithTitle` 的**第一个**按钮 = 最右 = 默认蓝 = 回车触发。因此先加主按钮（确认），后加取消。

### 5.3 非英文取消按钮需显式绑 Esc

AppKit 只对标题为 "Cancel" 的按钮自动绑 Esc。中文「取消」须手动 `setKeyEquivalent("\u{1b}")`。

### 5.4 `block2` 的 `IntoBlock` 只支持 `Fn`（不支持 `FnOnce`）

sheet 完成回调里要把 `oneshot::Sender` 移出去 `send()`，但闭包只能 `Fn`。解法：`Arc<Mutex<Option<Sender>>>` 槽位，回调内 `take()` 后 send。

### 5.5 Rust 2021 精准捕获 + Send 约束（两个连锁坑）

- `async fn` 参数中的裸指针 `*mut c_void` 跨 `await` 存活 → future 非 Send → Tauri 命令编译失败。
  解法：包装 `pub struct ParentWindow(*mut c_void)` 并 `unsafe impl Send`，只携带地址、无共享可变状态。
- 闭包内直接访问 `parent.0` → Rust 2021 精准捕获只捕裸指针字段（非 Send）。
  解法：经 `fn ptr(&self)` 方法调用，强制捕获整个 `&self` 包装体。

### 5.6 feature 依赖链（objc2-app-kit）

- `NSModalResponse` 宿主是 `NSApplication` 的 feature，`NSAlert` 不隐含，**必须并列声明**。
- `NSAlert`/`NSButton` 的方法还依赖 `NSControl`/`NSResponder`/`NSView` feature。

### 5.7 else 牢记

- App 图标**编译期内嵌** `include_bytes!("../../../icons/128x128@2x.png")`：dev 环境裸二进制运行时 `NSApplicationIcon` 不可靠，显式 `setIcon` 保证真图标（与 `embedded_rules.rs` 内嵌哲学一致）。
- **无超时设计**：与旧 `mole_system_confirm` 的 60s 超时不同 —— 原生对话框不存在「前端崩溃导致永久挂起」的 webview 场景。
- sheet 期间 alert 保活：回调闭包捕获 `alert.clone()`；handler 由 AppKit copy 持有。
