# 自更新功能实现总结

> 本文档记录 2026-09 实现的 Molan 自更新（Self-Update）功能全貌，供后续开发参考。
> 当前状态：代码已全部落地并编译通过，**尚未发布**。上线前需完成文末「待办清单」。

---

## 1. 功能概述

在系统托盘 Dashboard 的右下角设置菜单（`BottomBar.tsx`）中实现「检查更新」：

- **检查**：启动后 5 秒静默检查一次 + 用户手动点击触发
- **提示**：发现新版本时菜单项右侧显示红色圆点徽标
- **安装**：官网版自动下载安装（Ed25519 签名校验）；MAS 版引导 App Store
- **更新源**：Gitee（主，国内快）+ GitHub（备，国际源），插件按数组顺序自动 fallback

---

## 2. 参考项目分析结论

| 项目 | 方案 | 借鉴点 | 不采用的原因 |
|------|------|--------|-------------|
| **Lemon Cleaner** | 纯 MAS 分发，无自更新代码 | MAS 版引导 App Store 的思路 | 无官网分发场景参考 |

**最终选型：`tauri-plugin-updater`**（Tauri 2 官方自更新插件）
- 功能等价 Sparkle（Ed25519 签名、增量更新、自动重启）
- 原生 Tauri 2 集成，保持 Rust 单栈
- 支持 JSON endpoint（自建 `latest.json`，零外部服务依赖）

## 3. 架构设计

### 3.1 双版本策略

| 版本 | feature | 更新源 | 检测方式 | 安装方式 |
|------|---------|--------|---------|---------|
| 官网完整版 | `full`（默认） | Gitee 主 + GitHub 备 | `GET latest.json` 固定 URL | tauri-plugin-updater 自动下载安装 |
| MAS 精简版 | `mas`（互斥） | App Store | 运行时检测 `_MASReceipt/receipt` 存在 | `open macappstore://showUpdatesPage` |

MAS 检测逻辑在 `self_update.rs::is_mas_build()`：
```
current_exe() → .parent() → MacOS/
             → .parent() → Contents/
             → Contents/_MASReceipt/receipt 是否存在
```

### 3.2 更新源 Endpoint 配置

**配置位置：`src-tauri/tauri.conf.json` → `plugins.updater`**

```jsonc
"plugins": {
  "updater": {
    "endpoints": [
      "https://gitee.com/tiyong/Molan/raw/master/update/latest.json",
      "https://github.com/tiyongLit/Molan/raw/main/update/latest.json"
    ],
    "pubkey": "<Ed25519 公钥 base64，当前为占位符>"
  }
}
```

- 插件自动按数组顺序尝试：Gitee 超时/失败 → fallback GitHub
- `pubkey` 必须替换为 `tauri signer generate` 生成的真实公钥

### 3.3 latest.json 格式（tauri-plugin-updater 规范）

**文件位置：Gitee 仓库 `update/latest.json`**（不在本项目源码内）

```jsonc
{
  "version": "0.2.0",
  "notes": "## 新功能\n- 网络监控修复",
  "pub_date": "2026-09-20T10:00:00Z",
  "platforms": {
    "darwin-aarch64": {
      "signature": "<Ed25519 签名 base64，来自 .sig 文件内容>",
      "url": "https://gitee.com/tiyong/Molan/releases/download/v0.2.0/Molan_aarch64.app.tar.gz"
    },
    "darwin-x86_64": {
      "signature": "...",
      "url": "..."
    }
  }
}
```

**`useSelfUpdate.ts` hook 能力：**

- `checkForUpdate(force?)`：检查更新，`force=true` 绕过 60s 最小间隔
- `installUpdate()`：官网版走 `download_and_install`；MAS 版走 `open_appstore`
- `dismissVersion()`：忽略当前版本（持久化到 `tauri-plugin-store` 的 `settings.json`）
- `state`：`{ checking, result, progress, installing, error }`
- `hasUpdate`：`available === true && latest_version !== dismissed`
- 内置 5s 延迟的启动静默检查（`useEffect` 一次性触发）

### 4.3 UI 交互设计（BottomBar.tsx）

```
菜单项渲染：
  检查中...            ← checking=true 时
  检查更新          ●  ← hasUpdate=true 时显示红点 (6px, #ff3b30)

点击行为（handleUpdateClick）：
  1. state.result?.available === true
     → moleMessage 提示版本号 → installUpdate()
     （MAS 版提示"前往 App Store"，官网版直接下载安装）
  2. 否则 → checkForUpdate(true) 强制检查
     → 检查后 200ms 读 state：error 提示失败 / 无更新提示"已是最新"
     → available=true 时红点出现，用户再次点击触发安装
```

## 5. 接口契约

### 5.1 SelfUpdateCheckResult（前后端共享类型）

```typescript
interface SelfUpdateCheckResult {
  available: boolean          // 是否有新版本
  source: string              // "gitee" | "github" | "app_store" | "none"
  latest_version?: string     // 远程最新版本
  current_version: string     // 当前运行版本
  release_notes?: string      // Release Notes (Markdown)
  download_url?: string       // 下载 URL（官网版）
  published_at?: string       // 发布日期 ISO8601
}
```

### 5.2 进度事件

```
事件名：self-update::progress
payload: { phase: "downloading" | "installing", progress: 0-100 }
```

下载回调签名（tauri-plugin-updater v2.11）：
`|chunk_length: usize, content_length: Option<u64>|` — **content_length 是 Option**，
计算进度时需 match 处理 None 情况（已踩坑修复）。

## 6. 上线前待办清单

### 6.1 生成签名密钥（必须）

```bash
pnpm tauri signer generate -w ~/.molan-key.txt
```

- **私钥**妥善保管，仅在打签名时使用（不要提交到 Git）
- **公钥**替换 `tauri.conf.json` → `plugins.updater.pubkey`（当前是 base64 占位符）

### 6.2 在 Gitee 仓库创建 latest.json（必须）

在 `https://gitee.com/tiyong/Molan` 仓库创建 `update/latest.json`，
格式见上文 3.3 节。

### 6.3 每次发版流程（手动，CI 后续自动化）

```bash
# 0. 前置：tauri.conf.json 的 bundle 段启用 "createUpdaterArtifacts": true，
#    并设置 TAURI_SIGNING_PRIVATE_KEY 环境变量；
#    两者缺一，tauri build 会因"有公钥无私钥"直接报错退出（不会生成 .app.tar.gz）
# 1. 本地构建
pnpm tauri build
# 产物：src-tauri/target/release/bundle/macos/Molan.app
# 以及 tauri 自动生成的 .app.tar.gz 及其 .sig

# 2. 签名
pnpm tauri signer sign ~/.molan-key.txt Molan.app.tar.gz
# 产出 .sig 文件

# 3. 创建 Gitee Release (tag vX.Y.Z)
#    上传附件：Molan.app.tar.gz + .sig

# 4. 更新 Gitee 仓库 update/latest.json：
#    - version 字段 → 新版本号
#    - signature 字段 → .sig 文件内容
#    - url 字段 → Gitee Release 附件下载地址
#    - commit + push

# 5. （可选）同步 GitHub Release + GitHub 的 latest.json
```

## 7. 设计决策记录 (ADR)

| 决策 | 理由 | 备选方案（被拒原因） |
|------|------|---------------------|
| tauri-plugin-updater 而非 Sparkle | Tauri 2 官方插件、Rust 单栈、Ed25519 签名等价 | Sparkle：Cocoa FFI 复杂，违反红线 1 |
| 自建 latest.json 而非 Releases API | Gitee/GitHub Releases API 返回格式不同，插件要求固定 JSON 格式；静态文件零服务端依赖 | 自写 API 解析：工作量大；Cloudflare Worker 代理：引入外部服务 |
| Gitee 主 + GitHub 备 | 国内访问 Gitee 稳定快速 | 纯 GitHub：国内访问不稳定 |
| MAS 用 `_MASReceipt` 运行时检测 | 同一份代码双版本行为正确，无需编译期区分 | Cargo feature gate：已用于其他能力，运行时检测对 MAS 审核更友好 |
| 检查间隔 60s + 启动 5s 静默 | 手动检查为主的隐私原则，静默检查不产生用户感知 | 纯手动：用户可能长期不知道有新版 |

### 已知限制

1. `pubkey` 当前是占位符——**发布前必须替换**，否则签名校验必然失败
2. `update/latest.json` 尚未在 Gitee 仓库创建——首次检查会 404 fallback 到 GitHub（也 404）→ 返回错误
3. 下载进度事件 `chunk_length` 语义是「当前分块结束时的累计字节数」，进度计算已按此处理
4. MAS 版 `_MASReceipt` 检测依赖应用已通过 App Store 安装；本地 debug 构建永远返回 false（走官网路径）
