# 自更新功能实现总结

> 本文档记录 Molan 自更新（Self-Update）功能的实现全貌与当前发布口径，供后续开发参考。
> 当前状态：功能已上线——`1.0.0-alpha.2` 起为真密钥构建；发布通道仅 Gitee（已全链路打通），
> GitHub 备用源在 `tauri.conf.json` 与清单生成脚本中均已留口子、尚未启用。
> 日常发版操作以 `docs/DEVELOPMENT.md` 为准；本文偏设计与实现细节，两者冲突时以 DEVELOPMENT.md 为准。

---

## 1. 功能概述

在系统托盘 Dashboard 的右下角设置菜单（`BottomBar.tsx` 齿轮下拉）中提供「检查更新」：

- **检查**：启动 5 分钟后首次静默检查 + 4 小时周期轮询 + 用户手动点击立即触发；
  受设置项 `autoCheckUpdate`（开关）与 `updateCheckInterval`（1/7/30 天）控制
- **提示**：发现新版本时托盘气泡齿轮按钮右上角显示红色圆点徽标（`UpdateBadge`）
- **安装**：官网版自动下载安装（Ed25519 签名校验）；MAS 版引导 App Store（保留代码，MAS 版已搁置）
- **更新源**：Gitee（主，当前唯一启用）；GitHub（备，端点与生成口子已留，见 3.2）

## 2. 参考项目分析结论

| 项目 | 方案 | 借鉴点 | 不采用的原因 |
|------|------|--------|-------------|
| **Lemon Cleaner** | 纯 MAS 分发，无自更新代码 | MAS 版引导 App Store 的思路 | 无官网分发场景参考 |

**最终选型：`tauri-plugin-updater`**（Tauri 2 官方自更新插件）
- 功能等价 Sparkle（Ed25519 签名、增量更新、自动重启）
- 原生 Tauri 2 集成，保持 Rust 单栈
- 支持 JSON endpoint（自建 `latest.json`，零外部服务依赖）

## 3. 架构设计

### 3.1 双版本策略

| 版本 | 检测方式 | 更新源 | 安装方式 |
|------|---------|--------|---------|
| 官网完整版（当前唯一维护） | `GET update/latest.json` 固定 URL | Gitee（GitHub 备源预留） | tauri-plugin-updater 自动下载安装 |
| MAS 精简版（搁置） | 运行时检测 `_MASReceipt/receipt` 存在 | App Store | `open macappstore://showUpdatesPage` |

MAS 检测逻辑在 `lib/manage/app_version.rs::is_mas_build()`：
```
current_exe() → .parent() → MacOS/
             → .parent() → Contents/
             → Contents/_MASReceipt/receipt 是否存在
```

> MAS 分支属双版本设计的保留代码（保持可编译即可）；项目当前只发布官网完整版。

### 3.2 更新源 Endpoint 配置（现状）

**配置位置：`src-tauri/tauri.conf.json` → `plugins.updater`**

```jsonc
"plugins": {
  "updater": {
    "endpoints": [
      "https://gitee.com/tiyong/Molan/raw/master/update/latest.json",   // 主源（已启用）
      "https://github.com/tiyongLit/Molan/raw/main/update/latest.json"  // 备源（预留口子）
    ],
    "pubkey": "…（真实 Ed25519 公钥已回填，minisign 指纹 C5C583F519D67852）"
  }
}
```

- 插件按数组顺序尝试，**成功即止**：Gitee 正常时不会访问 GitHub 备源
- GitHub 备源当前未启用（仓库与 `update/latest.json` 未建立，访问会 404）——但口子已留好：
  - **配置层**：endpoints 第二条已就位，GitHub 上线后无需改代码
  - **脚本层**：`GITHUB_REPO=<仓库地址> bash scripts/gen-latest-json.sh` 会额外生成
    `release/latest.github.json`（url 指向 GitHub Release），把它放到 GitHub 仓库的
    `update/latest.json` 即可

### 3.3 latest.json 格式与生成链路

**唯一清单文件位置：本仓库 `update/latest.json`**（提交推送后由 App 通过 raw URL 读取）。

生成链路（单文件直出，无人工复制步骤）：

```
pnpm build:mac（scripts/build-dmg.sh）
  └─ 构建 → 产物收集到 release/（dmg / .app.tar.gz / .sig）
  └─ scripts/gen-latest-json.sh → 直接写入 update/latest.json
```

```jsonc
{
  "version": "1.0.0-alpha.2",        // 不带 v 前缀（与 Gitee Release tag 完全一致）
  "pub_date": "2026-10-06T03:50:05Z",
  "platforms": {
    "darwin-aarch64": {
      "signature": "<Ed25519 签名 base64，来自 .sig 文件内容>",
      "url": "https://gitee.com/tiyong/Molan/releases/download/1.0.0-alpha.2/Molan_1.0.0-alpha.2_aarch64.app.tar.gz"
    },
    "darwin-x86_64": { "signature": "...", "url": "..." }
  }
}
```

**`release/` 与 `update/` 的分工（不可混）**：

| 目录 | 角色 | 内容 | Git |
|------|------|------|-----|
| `release/` | 构建产物暂存（待上传 Gitee Release） | dmg、.app.tar.gz、.sig | gitignore |
| `update/` | 发布源（App 读取的就是它） | `latest.json`（唯一清单） | 跟踪，随发版提交 |

## 4. 已实现代码清单

### 4.1 后端 (Rust)

| 文件 | 关键内容 |
|------|---------|
| `src-tauri/Cargo.toml` | `tauri-plugin-updater = "2"` |
| `src-tauri/tauri.conf.json` | `plugins.updater`（endpoints + pubkey）、`bundle.createUpdaterArtifacts: true` |
| `src-tauri/capabilities/default.json` | `"updater:default"` 权限 |
| `src-tauri/src/events.rs` | `EVT_APP_VERSION_PROGRESS = "app-version::progress"` + `AppVersionProgressPayload` + `emit_app_version_progress()` |
| `src-tauri/src/lib/manage/app_version.rs` | 核心逻辑：`check_for_update` / `perform_update` / `is_mas_build` / `open_appstore` |
| `src-tauri/src/controllers/app_version.rs` | 3 个命令薄层（`controllers/mod.rs` 导出，`lib.rs` 注册） |
| `src-tauri/src/lib.rs` | 注册 updater 插件 + 3 个命令到 `generate_handler!` |

**命令清单：**

| 命令 | 签名 | 说明 |
|------|------|------|
| `mole_app_version_check` | `async fn(app: AppHandle) -> Result<AppVersionCheckResult, String>` | 检查更新；MAS 版直接返回 `source: "app_store"` |
| `mole_app_version_install` | `async fn(app: AppHandle) -> Result<(), String>` | 下载安装（带进度事件推送），完成后 `app.restart()` |
| `mole_app_version_open_appstore` | `fn() -> Result<(), String>` | MAS 版引导：`open macappstore://showUpdatesPage` |

> `mole_` 前缀属 API 契约，品牌改名 Molan 时刻意未动。

### 4.2 前端 (TypeScript)

| 文件 | 关键内容 |
|------|---------|
| `src/constants/tauri-commands.ts` | `CMD_MOLE_APP_VERSION_CHECK / _INSTALL / _OPEN_APPSTORE` + `TAURI_COMMANDS` 注册 |
| `src/constants/tauri-events.ts` | `EVT_APP_VERSION_PROGRESS = 'app-version::progress'` |
| `src/hooks/useTauri.ts` | re-export 事件常量 |
| `src/types/mole.ts` | `AppVersionCheckResult` 接口 |
| `src/hooks/useAppVersion.ts` | 自更新 hook（见下） |
| `src/pages/Dashboard/BottomBar.tsx` | 齿轮按钮红点徽标（`UpdateBadge`） |
| `src/pages/Dashboard/useDashboardMenuActions.ts` | 菜单动作统一入口（齿轮下拉与托盘原生右键菜单共用） |

**`useAppVersion.ts` hook 能力：**

- `checkForUpdate(force?)`：检查更新；`force=true` 绕过所有节流（用户手动触发）
- `installUpdate()`：官网版走 `mole_app_version_install`；MAS 版走 `open_appstore`
- `dismissVersion()`：忽略当前版本（持久化到 `settings.json` 的 `appVersion:dismissedVersion`）
- `state`：`{ checking, result, progress, installing, error }`
- `hasUpdate`：`available === true && latest_version !== dismissed`
- 后台静默调度（VS Code 式）：
  - 启动 5 分钟后首次检查（`SILENT_CHECK_DELAY_MS`）
  - `appVersion:lastCheckedAt` 持久化，重启不重查
  - 失败退避：间隔按 1h 基数翻倍，上限 8 小时；失败次数持久化
  - 4 小时周期轮询（覆盖长会话）
  - 调度前读设置项：`autoCheckUpdate=false` 时不动定时器（手动入口仍可用）

### 4.3 UI 交互设计

```
齿轮按钮（BottomBar.tsx）：
  hasUpdate=true → 右上角红点徽标 UpdateBadge（6px，#ff3b30）

菜单项渲染（齿轮下拉与托盘原生菜单同一套）：
  「检查更新」恒显示，不随 checking 变文案/置灰

点击行为（useDashboardMenuActions.handleUpdateClick）：
  1. checking=true → 直接忽略（后台静默检查进行中，结果数秒内落地）
  2. state.result?.available === true
     → moleMessage 提示版本号 → installUpdate()
     （MAS 版提示"前往 App Store"，官网版直接下载安装）
  3. 否则 → checkForUpdate(true) 强制检查
     → 200ms 后读 state：error 弹失败提示 / 无更新提示"已是最新"
     → available=true 时红点出现，再次点击触发安装
```

## 5. 接口契约

### 5.1 AppVersionCheckResult（前后端共享类型）

```typescript
interface AppVersionCheckResult {
  available: boolean          // 是否有新版本
  source: string              // "gitee" | "github" | "app_store" | "none"
  latest_version?: string     // 远程最新版本
  current_version: string     // 当前运行版本
  release_notes?: string      // Release Notes (Markdown)
  download_url?: string       // 下载 URL（官网版）
  published_at?: string       // 发布日期 ISO8601
}
```

### 5.2 进度事件

```
事件名：app-version::progress
payload: { phase: "downloading" | "verifying" | "installing", progress: 0-100 }
```

下载回调签名（tauri-plugin-updater v2.11）：
`|chunk_length: usize, content_length: Option<u64>|` — **content_length 是 Option**，
计算进度时需 match 处理 None 情况（已踩坑修复）。

- **签名密钥：已完成**。私钥 `~/.molan-key.txt`（无密码，chmod 600）；公钥 minisign
  指纹 C5C583F519D67852 已回填 `plugins.updater.pubkey` 并通过签名预检。
  多设备迁移与轮换流程见 DEVELOPMENT.md 第三节
- **Gitee latest.json：已完成**。`update/latest.json` 随本仓库维护（master 分支
  `update/` 目录），由构建脚本自动生成，人工只做 commit + push
- **发版流程**：见 `docs/DEVELOPMENT.md` 第四节。核心顺序要求：
  **必须先传完 Gitee Release 附件，再推送 update/latest.json**（顺序反了用户下载 404）
- **通道行为**（已实测）：Gitee Release 附件匿名可下载；raw 分支文件
  `.../raw/master/update/latest.json` 匿名可读，约 60 秒 CDN 缓存

## 7. 设计决策记录 (ADR)

| 决策 | 理由 | 备选方案（被拒原因） |
|------|------|---------------------|
| tauri-plugin-updater 而非 Sparkle | Tauri 2 官方插件、Rust 单栈、Ed25519 签名等价 | Sparkle：Cocoa FFI 复杂，违反红线 1 |
| 自建 latest.json 而非 Releases API | Gitee/GitHub Releases API 返回格式不同，插件要求固定 JSON 格式；静态文件零服务端依赖 | 自写 API 解析：工作量大；Cloudflare Worker 代理：引入外部服务 |
| Gitee 主 + GitHub 备 | 国内访问 Gitee 稳定快速 | 纯 GitHub：国内访问不稳定 |
| MAS 用 `_MASReceipt` 运行时检测 | 同一份代码双版本行为正确，无需编译期区分 | Cargo feature gate：已用于其他能力，运行时检测对 MAS 审核更友好 |
| 检查间隔可控 + 启动 5 分钟静默 | 手动检查为主的隐私原则，静默检查不产生用户感知；节流/退避/持久化避免频繁打扰 | 纯手动：用户可能长期不知道有新版 |
| 清单唯一化：脚本直接写 `update/latest.json` | 消除 release/ 与 update/ 两份副本与人工 cp 步骤，发布少一个出错点 | 保留 release/latest.json 草稿再手工复制：两步易失同步（改造前形态） |
| GitHub 备源先留口子不启用 | 当前只有 Gitee Release 真实存在；口子在配置 + 脚本变量两层留好，上线零改码 | 立即生成双份清单：备源仓库未建，文件会指向 404 |

### 已知限制

1. GitHub 备源尚未上线（endpoint 与生成口子已留；仓库未建，Gitee 失败时备源暂时也会 404）
2. 下载进度事件 `chunk_length` 语义是「当前分块结束时的累计字节数」，进度计算已按此处理
3. MAS 版 `_MASReceipt` 检测依赖应用已通过 App Store 安装；本地 debug 构建永远返回 false（走官网路径）
4. 版本线备忘：`1.0.0-alpha.1` 为占位公钥构建，**永远收不到自更新**；`1.0.0-alpha.2` 起为真密钥构建
